# db-desktop-backup

独立的 Windows 数据库桌面备份程序，目前支持将服务器指定 PostgreSQL Database 完整复制到对应本地 Database，后续计划扩展其他数据库类型。多个任务共用串行队列，只在本程序运行期间执行。

## 启动

需要 Windows、Python 3.12 或更新版本（包含 Tkinter），以及 PostgreSQL 的 `pg_dump`、`pg_restore`、`psql` 工具。程序本身不依赖额外的 Python 第三方包。

双击 `启动程序.bat`，或在项目目录执行：

```powershell
python -m dbbackup
```

默认工具目录自动检测本机 PostgreSQL 安装路径，也可以在界面中手动选择包含上述三个工具的 `bin` 目录。

已知环境：服务器 PostgreSQL 16（用户提供），本地工具 18.1。PG 18 工具支持导出 PG 16，恢复目标必须不低于所用导出工具的大版本；源库涉及的扩展仍需在本地提供相应兼容版本。

## 配置与使用

1. 点击“添加配置”，填写服务器地址、端口、账号、密码和源数据库名。
2. 填写本地账号、端口和目标数据库名。本地地址仅接受 `localhost`、`127.0.0.1`、`::1`。
3. 指定目标数据库就是允许被本任务完整替换的 Database。源库和目标库可以不同名；其他数据库不会被纳入替换。
4. 本地账号需要建库权限，并拥有已有目标库，或具有超级用户权限。源端账号需要读取全部待备份对象的权限。
5. 保存后选中任务，点击“测试连接”；再点击“一键备份选中项”。

目标库可以尚不存在，首次成功后将创建。`postgres`、`template0`、`template1` 不允许作为备份目标。

“参与启动自动备份和全部备份”控制是否加入批量操作；未启用的配置仍可以手动执行。“运行期间定时备份”按每项任务单独设置间隔，首次定时触发在完整间隔之后。

“保存设置”可以选择下次启动时等待手动操作，或自动逐个执行已启用任务。新配置默认关闭定时，程序默认关闭启动自动备份。

## 停止与调度规则

- 所有手动、自动启动、定时任务统一串行执行。
- 相同任务已在执行或排队时，不重复加入。
- “停止当前”取消当前任务，等待队列随后继续执行。
- “取消选中排队”只取消选中配置尚未开始的任务。
- “停止全部”停止当前任务、清空等待队列，并暂停定时调度。
- “暂停 / 恢复定时”不影响当前任务，恢复后重新计算间隔。
- 关闭窗口会请求停止任务，等待清理完成再退出。
- 程序关闭期间不执行，也不在重新打开后补跑所有错过的周期。

切换数据库名称的短事务期间不会强行终止子进程；若停止请求恰好发生在最终切换时，任务可能已成功完成。界面将报告实际结果。

## 备份与替换方式

```text
检查版本、权限和目标库连接占用
    → pg_dump 导出指定服务器源库
    → 创建独立本地临时库
    → pg_restore 在单个事务中恢复
    → 验证恢复成功并统计表和视图
    → 在一个事务中切换新旧数据库名称
    → 清理旧库和临时导出文件
```

每项任务最终保留一个可查询的本地目标库，不另外长期保存 `.dump` 文件。执行过程中暂时存在新旧两份，以便失败或停止时保留上一份成功副本。

内容包含表结构、数据、序列、索引、约束、视图及函数等数据库对象。实例级账号和角色不复制；恢复对象归本地执行账号所有，源端授权、表空间位置、逻辑复制发布与订阅不迁入本地副本。数据库自身的区域设置、所有者、数据库级参数与授权也不承诺按源端复制。

校验目前包括官方恢复工具执行成功和恢复后的目录查询，不做逐行校验和比对。服务器在导出后发生的修改将在下一次备份中体现。

本地目标库若有其他连接，任务会失败并保留原库，不强制断开其他程序。恢复过程中又出现目标库连接时，切换可能失败，此时改名事务回滚。

占用提示会列出检查时的连接总数，以及最多 10 个连接的应用名、数据库后端 PID、用户、地址、状态和进程类型，不读取这些连接正在执行的 SQL 内容。`idle` 仍是未断开的连接；关闭查询页签不一定会断开连接，需要在数据库客户端中明确断开该数据库，或停止连接这个库的本地程序。PID 是数据库后端的标识，不等同于客户端应用的进程号。

若本地应用需要持续使用已有数据库，可以在该任务配置中指定一个新的、专用于备份的本地目标库名称。源库名称保持不变，其他本地库不受影响。修改目标库前应先确认备份应保存在哪里，不要为了避开占用而随意选择现有库。

该程序用于逐库逻辑副本，不提供 PostgreSQL 整个实例的物理备份或时间点恢复。

## 配置、密码与执行记录

默认保存在项目目录的 `data/` 中：

- `config.json`：任务和设置；密码用 Windows DPAPI 加密保存，与当前 Windows 用户环境绑定。
- `state/<任务标识>.json`：最后执行结果及最近成功时间。
- `working/<执行标识>/journal.json`：执行阶段及本次临时数据库的标识。

密码不放在命令行中，通过子进程环境传给 PostgreSQL 工具；不要把整个 `data/` 目录提交到 Git 或公开分享。复制配置到另一台电脑或另一个 Windows 用户后，原加密密码可能无法解密，需要重新配置。

程序同时只允许一个实例使用同一数据目录。可用 `python -m dbbackup --data-dir <目录>` 选择独立配置目录；不要让不同目录的程序同时写同一个目标库。

正常完成、失败和取消后会清理本次临时库和文件。若断电、强制结束进程，或清理因连接、权限而失败，可能留下 `_dbbackup_stage_...`、`_dbbackup_old_...` 临时库和对应执行记录。启动时会提示，不会自动删除结果不明确的数据库；此类情况需要根据执行记录中的名称、OID 和目标库状态处理，不应仅凭名称前缀批量删除。

## 测试

测试使用 pytest（仅开发需要）。普通测试不连接现有 PostgreSQL：

```powershell
python -m pytest -q
```

完整集成测试由程序在 `.test_runtime/` 下创建独立的 PostgreSQL 实例，只监听本机临时端口；不使用现有实例、业务数据或保存的账号，结束后停止并清理：

```powershell
$env:RUN_PG_INTEGRATION = '1'
python -m pytest -q
```

可以用环境变量 `PGBACKUP_TEST_BIN` 指定测试用 PostgreSQL `bin` 目录。Windows 沙箱可能阻止独立实例启动，这种情况下需在允许启动本地测试进程的环境运行。

测试验证配置密码保护、串行与去重、定时调度、取消子进程，以及真实导出恢复、完整替换、无关库保留和切换事务回滚。真实服务器 PG 16 的连接、扩展及生产数据尚未验证。
